# astrbot_plugin_guardian

QQ 机器人守护系统管理插件（AstrBot v4+）。

## 设计

守护本体运行在 **AstrBot 进程之外**（PowerShell 常驻循环），才能守护 Docker 引擎、napcat 容器和 AstrBot 自身——进程内组件无法守护自己。本插件负责：

1. **自动部署**：插件加载时检测守护循环是否在运行；未运行则把内置守护脚本释放到工作区 `watchdog/` 目录并拉起（第二道防线）
2. **开机自启**：`部署` 指令可写入启动文件夹 bat
3. **手机遥控**：管理员用 `/守护` 指令随时查状态、重启容器、出新码、取二维码

## 指令（仅管理员）

| 指令 | 说明 |
|---|---|
| `/守护` | 查看守护状态摘要 |
| `/守护 部署` | 释放脚本 + 拉起循环 + 写开机自启 |
| `/守护 重启容器` | 重启 napcat 容器 |
| `/守护 重启守护` | 杀掉守护循环并重新拉起 |
| `/守护 日志` | 查看守护日志最后若干行 |
| `/守护 二维码` | 提取容器当前登录二维码图片 |
| `/守护 新码` | 停容器-清登录数据-重启出新码 |

## 内置守护能力（qq-watchdog.ps1）

- Docker 引擎掉线自动拉起；引擎假死连续探测失败才强杀重启（防误杀启动中）
- napcat 容器停止自动启动
- AstrBot 端口未监听自动拉起进程
- QQ 卡死先重启容器 ×2 → 再清登录数据出新码（60 分钟冷却）
- 新二维码自动渲染到 `qq登录二维码_最新.png`
- 全链路 docker 调用带硬超时，单轮 8 分钟兜底，防假死拖垮循环

## 文件布局（部署后）

- `<工作区>/watchdog/qq-watchdog.ps1` 单轮检测脚本
- `<工作区>/watchdog/watchdog-main.ps1` 常驻循环（带 PID 防重锁）
- `<工作区>/watchdog/status.txt` 状态速查
- `<工作区>/watchdog/watchdog.log` 运行日志
- 启动文件夹 `QQ机器人守护.bat` 开机自启
